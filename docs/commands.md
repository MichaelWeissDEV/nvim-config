# Commands

This configuration defines a structured set of custom user commands designed to give you full visibility and control over health, keybindings, commands, formatters, linters, and language tools.

## Architecture & How Commands Are Implemented

Every command in this configuration is registered via the central registry module at `lua/util/command_registry.lua`. Rather than calling `vim.api.nvim_create_user_command` ad-hoc across dozens of files, registration goes through a single schema-validated pipeline:

```lua
-- Example from lua/config/commands.lua
local cmdreg = require("util.command_registry")

cmdreg.command({
  name = "NvimConfigHealth",
  desc = "Run the structured health report for this config",
  category = "Diagnostics",
  example = ":NvimConfigHealth",
  fn = function()
    vim.cmd("checkhealth nvim-config")
  end,
})
```

### Why a Central Registry?

1. **Single Source of Truth**: The registry powers both the live runtime scratchpad `:NvimCommands` and this static documentation page (generated by `scripts/generate-docs.lua`).
2. **Predictable Discovery**: All commands belong to a defined category (`Diagnostics`, `Documentation`, `Formatting`, `LSP`, `Tools`, `Debugging`).
3. **Safety & Clean Teardown**: Invalid arguments or duplicate command names are caught at startup rather than during editing.

### How to Initialize & Discover Commands at Runtime

You can explore and run commands immediately using these built-in meta-commands:

- **`:NvimCommands`**: Opens a live scratchpad buffer listing every registered command grouped by category, with its description and usage example.
- **`:NvimKeymaps`**: Opens a live scratchpad buffer listing all custom keybindings grouped by subsystem, showing their mode, LHS sequence, and destination function.
- **`:NvimConfigHealth`**: Runs `:checkhealth nvim-config`, displaying status of Neovim version, Lua runtime, external CLI dependencies, LSP servers, formatters, and treesitter parsers.
- **`:NvimDocs`**: Opens local HTML documentation in your browser, or drops into `:help nvim-config` if HTML is unbuilt.

### Keymaps Connected to Commands

Most frequent commands have direct `<leader>` keymap bindings:

| Command | Keymap | Subsystem | Purpose |
| :--- | :--- | :--- | :--- |
| `:Format` | `<leader>cf` | Formatting | Format current buffer using configured formatter |
| `:FormatToggle` | `<leader>uf` | Formatting | Toggle format-on-save (buffer-local; add `!` for global) |
| `:FormatStatus` | `<leader>uF` | Formatting | Display current format-on-save status and provider |
| `:LinterStatus` | `<leader>cl` | Linting | Display configured linters for current buffer |
| `:DebuggerStatus` | `<leader>ds` | Debugging | Check DAP debug adapter binary installation status |
| `:NvimConfigHealth` | `<leader>ch` | Diagnostics | Run comprehensive config healthcheck |
| `:NvimCommands` | `<leader>?` | Documentation | Browse all custom commands in a floating buffer |
| `:NvimKeymaps` | `<leader>fk` | Documentation | Fuzzy find keymaps via Telescope |
